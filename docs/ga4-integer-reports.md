## Complete, bounded reports

Accept one to five ordered pages, at most 64 KiB each, using actual recorded request offsets and one unchanged request limit of 1–250. At most 1,000 total rows are supported. Every page must have the exact expected headers/order/types and stable total row count. Offsets equal all previously accepted rows; page size equals the remaining expected rows up to the fixed limit. Require full completion, with no skipped, repeated, empty extra or incomplete page. Unique dimension tuples use JSON framing to avoid delimiter collisions; rows preserve provider order.

Strict objects reject unknown/case-aliased/duplicate decoded keys, trailing documents, malformed UTF-8 and unsupported types/nulls. Header arrays and row widths must match exactly. Omitted protobuf-default zero `rowCount`/empty `rows` are accepted only as a complete zero-row observation; explicit empty arrays are also valid. Ordinary JSON whitespace is accepted. The subset uses numeric int32 `rowCount`, named `TYPE_INTEGER` and camelCase fields; quoted row counts/numeric enum representations are unsupported.

Metric values are canonical nonnegative integer strings of at most 18 digits, preserved exactly beyond JavaScript's safe integer range. Unsupported signed/fractional/exponent values fail without floating point, truncation or coercion. No totals or ratios are computed: user/session metrics may be nonadditive across dimensions or dates. Empty observations remain empty; missing days/rows are never filled with zeros. Provider-reported zero is accepted only when trusted metadata and response quality are unrestricted. Ordinary dimension text, including `(not set)` and empty strings, is preserved without date/acquisition interpretation; values are at most 1,024 UTF-8 bytes without control/replacement characters or `RESERVED_` aggregate values. Financial/duration/float/custom/expression metrics, comparisons, cohorts and requested aggregates are outside this subset. The future transport must construct the recorded request accordingly.
