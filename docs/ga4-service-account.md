# GA4 service-account authorization

Existing [#26](https://github.com/theroisey/else/issues/26) now includes a bounded backend service-account exchange. It is not yet wired to public setup, background jobs or measured workspaces. No provider account is configured or contacted in tests. A service-account key alone never proves property access or client ownership; those require the subsequent exact property and report checks.

The contract is verified against the official Go OAuth2 implementation at [c624b89dadc3221560b7345c090bbe69e90808ee](https://github.com/golang/oauth2/blob/c624b89dadc3221560b7345c090bbe69e90808ee/jwt/jwt.go) and its [Google service-account configuration](https://github.com/golang/oauth2/blob/c624b89dadc3221560b7345c090bbe69e90808ee/google/google.go). The official flow signs an RS256 assertion with issuer, scope and token-endpoint audience and POSTs assertion plus the JWT-bearer grant type. Google's fixed token endpoint is https://oauth2.googleapis.com/token. The library's alternate audience/subject/universe/ID-token options are outside this supported contract. Official Google Analytics [Data API scope declarations](https://github.com/googleapis/googleapis/blob/ed6832a8b8254885e1ddc352bb1dc30b7f26f950/google/analytics/data/v1beta/analytics_data_api.proto) and [Admin API declarations](https://github.com/googleapis/googleapis/blob/ed6832a8b8254885e1ddc352bb1dc30b7f26f950/google/analytics/admin/v1beta/analytics_admin.proto) accept analytics.readonly.

The parser accepts at most 16 KiB of a normal service_account JSON document with an iam.gserviceaccount.com email, bounded key ID, fixed token_uri and the ordinary googleapis.com universe. It rejects duplicate/unknown fields, impersonation/audience settings, alternate token endpoints and unsupported signing material. Optional unused Google metadata stays scalar and is never followed as a URL. PKCS#8 two-prime RSA integers are bounded before x509 validation/precomputation; supported keys are 2048–4096 bits with exponent 65537. Raw credential bytes remain caller-owned and must be cleared and encrypted after authorized setup. Go strings/RSA objects are garbage collected; this code does not claim complete memory erasure.

Assertions use only analytics.readonly, the fixed audience, current issued time and one-hour expiry. The token exchange constructs its own fixed-origin [bounded provider HTTPS client](provider-https.md): verified TLS, public DNS pinning, no redirects/proxies/cookies, body/header/deadline/admission limits. Credentials never become query parameters. No direct self-signed JWT access token, endpoint discovery, cached token, refresh loop or automatic retry exists. Run exchange inside bounded background work; do not add it to dashboards or CRUD requests.

Only an exact Bearer token with a bounded printable ASCII value, numeric 60–3600 second lifetime and absent/exact read scope is accepted. Unknown/duplicate fields, errors, ID tokens, malformed/short/overlong lifetimes and canceled responses fail atomically with a fixed unavailable error. Access tokens stop being usable thirty seconds before expiry. Neither credential nor token can be JSON serialized or formatted into logs; Authorization is available only to trusted backend provider code. Network failure does not establish revoked credentials or failed ownership.

Synthetic RSA tests verify the signature, exact scope/audience/issuer/time claims, absence of impersonation and private-key transmission, fixed token request contract, endpoint/universe/key refusal, response privacy, cancellation/no-retry and near-expiry/serialization/log boundaries. Production transport TLS/DNS/bounds remain separately covered by providerhttp tests. Real property authorization, fresh metadata compatibility, reporting, durable sync and UI acceptance remain open under this same issue. No new issue or live activation is required for this implementation work.
