# Bounded password work

[#111](https://github.com/theroisey/else/issues/111) supplies a resource-readiness slice under #32. The existing Argon2id operation uses 19 MiB, two iterations and one lane. Request-context cancellation cannot preempt that CPU/memory work, and the per-peer/email limiter alone does not bound concurrent varied-email attempts.

The actual API creates one `BoundedPasswords` instance shared by identity and administration. It admits at most two synchronous hash/verify operations per process. Admission is nonblocking, with no request queue or CPU goroutine that can outlive its accounting slot. Success, error and panic release the slot only after underlying work stops. Already-canceled work is rejected before admission; a canceled operation's completed result is discarded before service mutation. Running Argon itself is not forcibly stopped. Two in-flight allocations are about 38 MiB of Argon workspace; this is not a cap on whole-process heap/RSS or retained garbage.

Argon parameters, PHC validation, random salts and constant-time verification remain unchanged. Known/unknown/disabled/wrong-password attempts retain the original verification policy. Saturation uses the same safe HTTP 503 `service_busy`, fixed text `This operation is temporarily unavailable. Try again.`, `Retry-After: 1` and normal JSON/no-store/correlation for login and admin user creation. It sets no session cookie or success state, exposes no account/credential details and creates no session/user/success audit. The existing per-peer/email throttle still precedes service login; this worker limit does not replace edge/distributed rate controls.

Optional context-aware password methods preserve the trusted legacy `Passwords` interface used by CLI/test callers. Actual API services use the shared bounded implementation; helpers check cancellation before/after legacy work too. One-time bootstrap uses its existing separate invocation, with cancellation checked before creating identity data. Adding new API password-consuming services requires the same shared instance; do not create independent limiters or unbounded Argon instances per request.

Deterministic unit tests hold two operations, reject both a third hash and verification without entering work, retain slots during cancellation, discard canceled results and recover after release/error/panic. Actual Argon round-trip tests prove unchanged encoded verification. Disposable PostgreSQL/real handlers hold only scheduling, retain real Argon hashes/verification and SQL, prove identical busy replies for known/unknown logins and shared admin hashing, fingerprint unchanged users/sessions/audits, then recover with exactly two successful login sessions/audits and one created user/audit. No successful authorization or provider data is mocked. Captured logs must omit private credentials/session/CSRF/email input.

Local targeted identity/admin/security-matrix tests and Go checks are required, followed by all six exact-head gates before ready. Results belong in #111/its PR/#32; this is not deployed login throughput proof. Final #32 still needs gateway/replica sizing, total database/worker connection ceilings, log sink/monitoring, provider/background isolation, secret mounts and backup/restore/rollback/target evidence. No deployment or crypto weakening is authorized by this resource slice.
