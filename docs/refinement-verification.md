# Release evidence, quiet operation and control geometry

Work is tracked by [#132](https://github.com/theroisey/else/issues/132), [#133](https://github.com/theroisey/else/issues/133) and [#134](https://github.com/theroisey/else/issues/134). Verification uses disposable databases and clearly synthetic accounts; it does not authorize a production rollout.

1. **Root causes.** Release Center had an immutable binary stamp but no remote evidence adapter. Fixed session polling and successful probe request logs created idle noise. Independently padded inputs/selects/buttons, helper placement and bottom-aligned action cells produced asymmetric localized filters. The final capacity gate additionally identified repeated role/permission joins for each directory candidate.
2. **Files changed.** Backend release modules/handler, API wiring, HTTP middleware and tests; Dockerfile/runtime and publication workflow/helpers; migration 28 and directory regression; shared frontend field/button/CSS primitives and operational forms/filters; authentication and release services/pages/tests; all five release locale dictionaries; documentation, decision notes and synthetic review captures. Existing business calculations and API mutation contracts remain intact.
3. **Architecture.** Server-only configuration, injected standard HTTP transport, strict repository/host grammar, verified TLS, four-second collection deadline, 2 MiB response cap, sanitized fixed failure reasons, coalesced 60-second cache and bounded manual revalidation. Fresh session/global release permission precedes provider access; responses remain no-store and reads create no database/audit records. [Detailed contract](releases.md).
4. **Evidence.** Running API uses its linker stamp. Latest artifact uses hashed GHCR manifests/configuration, immutable SHA identity, validated OCI metadata and the matching GitHub commit. Running-image provenance independently matches that registry evidence to the binary stamp. Publication completion uses the successful main CI publication job. Digest-matching attestation presence is a separate observation; CI cryptographically verifies the promoted tested digest.
5. **Honest unavailable states.** No deployment source exists. The API cannot inspect the host's enclosing container digest or independently verify attestation signatures. Missing publication time stays null; older incomplete labels, missing credentials, permission/package incompatibility and remote failures remain explicit. A fine-grained PAT cannot authenticate a private GHCR package.
6. **Logs.** Fast expected successful health/readiness/session reads use DEBUG. Failures, unexpected requests, slow responses, cancellations, panics, write failures and security-relevant mutations retain correlated operational records; upstream secrets/bodies/errors never enter diagnostics.
7. **Sessions.** Removed unconditional minute polling. Absolute expiry, focus/reconnect, protected-request denial, logout and private-cache clearing retain their behavior. Untouched idle tabs discover server revocation on the next relevant event/request. Real API and fake-clock regressions cover these boundaries.
8. **Docker.** One application image/container and one persistent volume remain. Probe interval is 30s, timeout 3s, three failures, startup grace 120s and startup cadence 5s. Required-process death still exits through the supervisor. Runtime credentials are not build arguments; PostgreSQL/worker do not inherit GitHub credentials. Pending migration 28 replaces only the directory function body and has a tested restoring Down migration.
9. **UI system.** Native SelectField and TextField share labels/body/descriptions/errors. CSS subgrids share the tallest translated label row; balanced filters collapse without positional offsets. Desktop controls are 40px, compact actions 32px, mobile/coarse targets 44px. Loading buttons preserve visible labels and geometry; resource-picker Enter does not accidentally save the surrounding form. [Layout review and screenshots](control-geometry.md).
10. **Rendered/accessibility review.** Built frontend served by the real Go API was reviewed across 35 routes, five locales, both themes and eight widths (320–2880px): 2,800 passing checks. Clients have 60 dedicated combinations with label associations, measured alignment/height/bounds, Enter applying the real filter and Tab navigation. Available/partial release layouts were reviewed separately with explicitly mocked evidence. Focus, reduced motion, native selection, descriptive errors and pending-button states remain usable.
11. **Verification.** Frontend: 562 tests in 49 files; lint, typecheck and production build pass. Browser: 26 real API workflows pass. Go race tests, vet and all seven command builds pass; publication/dependency/metadata/recovery boundary tests and actionlint pass. npm audit reports zero vulnerabilities. Directory rollback/reapply compares results and ACLs and tests fresh revocation. The unchanged capacity gate passes at 20/50/100 users and the mixed two-API/two-worker rehearsal: 3,000 valid responses, 30 writes, no timeouts; maximum directory-page P95 998.682ms versus the prior failing 2,409ms. This is a synthetic API rehearsal, not a deployed SLA. The complete PostgreSQL suite passes (557.243s), including all 28 migrations, and the final single-container initialization/persistence/offline restore/process-failure suite passes. Exact-commit CI/publication evidence is recorded in the linked issues before closure.
12. **Operator steps.** Set server-runtime `GITHUB_REPOSITORY=theroisey/else` and an appropriate read-only `GITHUB_TOKEN`, then restart through the normal deployment process. Fine-grained repository permissions are Contents/Actions/Attestations read; private packages require classic read:packages plus applicable repository/package/SSO access. Host Docker registry login is separate. Select the verified image digest and use the existing backup/upgrade process; code publication alone never opens production traffic.

Local checks use the current worktree candidate where an exact committed archive is not yet available. The managed workspace denies access to the official Go vulnerability feed (`vuln.go.dev`), so that exact scanner command must pass in the mandatory CI dependency gate; its failure is not suppressed or replaced with a different scan. Main CI rebuilds once from the exact published commit, runs all six gates, promotes that saved tested image, attests its registry digest, verifies the signature/source policy and rehearses pulling the published image with retained data. The publication job does not rebuild after verification. See [production operation](production-readiness.md) for capacity, migration and recovery limits.
