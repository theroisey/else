# Bounded trusted-provider HTTPS requests

[#121](https://github.com/theroisey/else/issues/121) supplies the internal `providerhttp` request boundary for later selected-provider adapters under #26/#27/#31. It performs no request at startup, reads no credentials, exposes no route and enables no account/setup/synchronization/success state. [Selected-provider catalog](selected-provider-catalog.md) and [workspace compatibility](provider-workspace-compatibility.md) are independently reviewed. Never expose this client as a user URL proxy.

The caller supplies a trusted stored canonical HTTPS origin, including the optional narrow WooCommerce store path. Lowercase ASCII dotted DNS hosts and implicit port 443 are required; userinfo, explicit ports, IP literals, query/fragment/percent/dot/trailing-slash base paths are refused. This accepts identity syntax, not account ownership. Future callers must obtain it under fresh client/management authorization and retain immutable provider binding, account proof and state/generation fences through external work and persistence.

Only adapter-owned GET/POST paths, explicit Authorization/Content-Type and bounded allowlisted query parameters are supported. Paths cannot override the origin or inject query/fragment/escapes/dot traversal. Credential-named query parameters, arbitrary headers, cookies, proxies and alternate hosts are unavailable. Bearer/Basic credentials stay in Authorization; JWT assertions belong only in a later reviewed token-exchange body. A trusted caller must still keep private values out of ordinary parameter fields. No raw error, URL, header or response is logged/audited.

Every connection resolves the original hostname, requires 1–8 addresses and rejects the entire answer if any address is unsafe. Validated IP literals are passed directly to the dialer, avoiding a second resolution. TLS verifies the original hostname/SNI against normal system trust, with TLS 1.2 minimum. Loopback/private/link-local/unspecified/multicast/shared/reserved/documentation/benchmark and conservative IPv6 transition/translation ranges are refused, including mapped IPv4 and zoned addresses. Ordinary IPv6 is restricted to 2000::/3 with special-use exclusions. This is deliberately conservative destination filtering, not a complete changing IANA registry or proof of provider identity. TLS-valid public endpoints can still be malicious: stored account authorization/ownership remains essential.

Share **one `Admission` instance per worker process** across every provider client. Two requests can run; excess work receives a fixed busy error without a queue or detached application request. Slots cover response consumption and started DNS/TCP/TLS cleanup. All replicas still require aggregate egress/worker limits; this is not distributed admission.

Total request budget is 10 seconds or the earlier caller deadline. DNS plus TCP is bounded to 2 seconds, TLS handshake to 3 seconds, response headers to 4 seconds, headers to 16 KiB, request body to 16 KiB, Authorization to 4 KiB, query to 4 KiB and ordinary responses to 64 KiB. `NewWithResponseLimit` accepts only the compiled 64 KiB or 256 KiB policy. The GA4 adapter uses 256 KiB solely for fixed-origin, field-projected compatibility metadata, whose API returns a catalog rather than only requested columns. Its token/property/report clients retain 64 KiB. No arbitrary byte limit or public limit input exists; chunked responses enforce the same cap. Go's transport ordinarily strips the request deadline from its dial context; each request uses an isolated transport with explicit budget-bound DNS/TCP/TLS and cleanup acknowledgement before releasing shared capacity. No insecure TLS or caller-provided production resolver/dial/trust hooks exist. Tests inject only package-private local TLS fixtures.

Keep-alive reuse and compression are disabled to make destination revalidation and bounded response handling explicit. This increases handshake overhead; use the client for bounded background work, not dashboard requests, and measure the future scheduled workload. Redirects are not followed, including same-host redirects. Only status 200, one application/json Content-Type, no Content-Encoding and complete nonempty bounded UTF-8 JSON return a body. All other outcomes discard private/partial data and return the same unavailable error. No business retry is implemented; quota/retry scheduling and current account/report semantics are adapter-owned work. Future interpreters must reject extra personal fields, partial/quality-invalid data and wrong account/period/currency before any persistence or public projection.

The package tests real isolated TLS hostname/trust, pinned dialing, mixed answers and DNS rebinding, headers/secret-free URLs, status/redirect/compression/header/body/JSON limits, cancellation and shared body/DNS cleanup lifetime. It does not call a live provider or prove deployed egress, provider policy, credentials, account access, report validity, retention or background ownership. Final local and six exact-head CI results belong in #121/its PR. Production network rules, proxy/CA trust, secret mounts, aggregate budgets and explicit rollout approval remain operating requirements.
