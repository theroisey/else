# Provider, credential and report boundaries

Exactly `ga4`, `woocommerce`, and `meta_ads` are supported. Connection metadata has seven safe fields: id, client_id, provider, state, revision, created_at, updated_at. Account identities, generations and ciphertext stay private. Client/account/provider identity is permanently owned; global account uniqueness prevents transferring it by recreating a client binding. Website association is independent context, not credential/account reassignment.

## Credentials and asynchronous work

Manual setup freshly checks active user/client and management grants, strictly validates bounded credentials, commits an audited key reservation, then encrypts and atomically installs/replaces credentials plus a durable queued job. HTTP 202 means local queued work, not provider access. Reads never contact providers or enqueue synchronization. No in-app OAuth, remote token refresh, provider writes or remote revocation is implemented. Local disable increments revision/generation, fences local work and explicitly requires manual provider revocation; history remains retained.

AES-256-GCM binds immutable client/connection/provider/purpose and version/key label. Versioned credential envelope framing/AAD is preserved byte-for-byte. One to eight protected 0400/0600 single-link regular key files retain decryption material. Independently random active keys use irreversible audited reservation counts capped at 2^24; failed encryption/persistence never refunds. Labels cannot reuse another fingerprint or vice versa. Restoration introduces fresh independent active material; source/backup-only keys remain decryptors. Inventory does not prove safe retirement or global material freshness. Undeclared rewind cannot be detected.

Two background workers share durable SQLite jobs, two running leases, fresh random claims and round-robin provider selection. Jobs allow up to three abandoned-lease attempts, 180-second leases and a 150-second operation ceiling; collection has a 120-second ceiling. Ordinary provider failure requires explicit user retry. Transactions end before external I/O. Before every request and final atomic publication, check requesting-user authority, active client, permanent connection identity/state/revision/generation, credential revision/generation and current lease. Rotation/replacement/disable/archive/revocation/expired or reclaimed claims fence obsolete work; requests already sent cannot be retracted.

Complete typed snapshots bind exact provider/client/connection/generation/period/currency and a content digest. A repeated successful period replaces one deterministic snapshot/revision. Failed refresh retains a previous valid current-generation report and its real success time. Missing/stale/failed/empty are distinct; old generations or different requested periods never become selected reports. Successful aggregates expire after 90 days with bounded audited pruning; identities, credentials, budgets, jobs and audits remain. Staleness starts at 24 hours. Analytics reads require clients.view + analytics.view independently of integration metadata/management.

## Outbound HTTP

The shared bounded client accepts only trusted canonical HTTPS origins and compiled adapter endpoints/headers/queries. Every DNS answer must contain only public permitted addresses; pin those addresses for TCP while TLS verifies the original hostname/SNI using distribution Mozilla trust. Reject IP literals, private/mixed/rebinding answers, redirects, proxies, cookies and provider navigation URLs. Syntax/public DNS/TLS prove neither legal ownership nor account authorization.

Two shared request slots include body consumption and cancelled DNS/TCP cleanup. No connection reuse avoids skipping destination revalidation. Bound DNS 2s, TCP 3s, TLS 4s and headers/body/whole request 10s, with earlier operation deadlines winning. Bound ordinary JSON to 64 KiB; only fixed GA4 projected compatibility metadata uses 256 KiB. Fixed response policy rejects compression, expanded/private/ambiguous JSON, partial pages, and raw provider errors. Credentials are Authorization headers or the fixed Google assertion body, never URL parameters/logs/audit/report fields. No provider work occurs at startup or on a dashboard read.

## GA4

Provision a service account with read access to the selected property. Strict service-account JSON accepts a bounded PKCS#8 RSA 2048–4096-bit key and fixed JWT RS256 exchange at oauth2.googleapis.com/token, with only analytics.readonly. Never trust credential token_uri/impersonation endpoints. Fixed Admin/Data origins verify exact property identity, nondeletion, timezone, compatible unblocked definitions, and complete aggregate tables.

Five compiled templates cover independent period summary, daily date, acquisition channel, devices and safe landing paths. Inclusive property-local dates are at most 31 days. Counts and bounded decimal attribution remain exact strings; period active users are not summed daily users. Ordered complete pagination caps at 1,000 rows and rejects sampling, thresholding, restrictions, truncation, data loss, expanded personal fields or unsafe landing queries/identifiers. Empty measured rows remain empty; no fake zero dates. Property configuration must itself exclude personal data from paths.

Official contract: [Google APIs commit ed6832a](https://github.com/googleapis/googleapis/tree/ed6832a8b8254885e1ddc352bb1dc30b7f26f950), including Admin/Data v1beta service/resource protos; fixed JWT exchange corroborated by [Google service-account OAuth contract](https://developers.google.com/identity/protocols/oauth2/service-account). Generated/source contracts establish API shape, not a supplied account's access or ownership.

## WooCommerce

Use a dedicated Read consumer key/secret (`ck_`/`cs_` plus 40 lowercase hex). Every request is GET with HTTPS Basic headers. Immutable canonical dotted DNS origin may include a narrow WordPress base path; no credentials, ports, escapes, queries or alternate endpoints. Vendor scope cannot be independently proved from syntax: provision a Read key even though a mistakenly broader key does not enable compiled writes.

Order-created and refund-created cohorts use separate explicit half-open UTC whole-second intervals of at most 31 days and selected USD/EUR/GBP/TRY/JPY/KWD currency. Request dp=6; exact source conversion refuses discarded nonzero subminor digits. Each collection is at most five pages/500 rows with unique increasing IDs, complete stable header counts and minimal nested field projections. Refund events require independent exact parent currency lookups, including older parent orders. Re-fetch both heads before acceptance; unchanged heads do not prove transactional multi-page consistency, so retain actual collection interval.

Order grand/lifetime negative-refund/remainder values describe that order-created cohort, across all standard statuses. Separately positive refund events describe their own creation cohort. Never subtract mismatched cohorts to invent revenue/cash settlement. Product-line groups contain numeric product/variation IDs, exact quantity/count/net/tax/grand, at most 50 lines/order and 1,000 groups. Unknown/deleted ID zero is honest; no inferred names, stock, paid sales, refunds-by-line or conversion. Line totals and order grand totals have different bases.

Official [WooCommerce 11.1.2 source](https://github.com/woocommerce/woocommerce/tree/2316335b1bce366178ce865d4e61a4c5e2219352) establishes wc/v3/v2 inherited serialization, CRUD date/count and authentication rules. [WordPress 6.8 field filtering](https://github.com/WordPress/wordpress-develop/blob/5744cd1a13f6da9f09db6d7f14ca66c5bf474ebe/src/wp-includes/rest-api.php) corroborates nested projections. The [REST documentation repository](https://github.com/woocommerce/woocommerce-rest-api-docs/tree/09431ca9a114289d298fd2a5d5b604ea50f6d197) is archived and cannot alone prove current support.

## Meta Ads

Provision a compatible user token with current ads_read/account access. Fixed Graph v26.0 checks permissions/current user/account before and after bounded daily collection. Keep only seven allowlisted aggregate fields over at most 31 account-local inclusive days; reject incomplete/colliding dates/cursors, wrong identity/currency/timezone, expanded private fields or provider links. API access is time-bounded access proof, not legal ownership.

Spend uses exact six-decimal micros; counts remain exact strings. Weighted CTR/CPC/CPM derive from exact sums with positive half-up six-place rounding and null for zero denominators. Missing dates remain absent. No attribution, revenue or ROAS is inferred. Official [Business SDK 26.0.2](https://github.com/facebook/facebook-python-business-sdk/tree/efd8423a2e595ea8d4c04eb824ce113f2f1d68cd) establishes Graph fields/version; provider permission/access policy is separately enforced at collection.

Synthetic isolated collector/TLS/credential/lease/cache/browser tests prove the stated contracts. They never establish real account credentials, legal ownership, deployed egress, provider throughput or a production availability guarantee. Private payloads/raw errors never become logs or CI artifacts.
